# Security Policy

Thank you for helping keep the projects maintained by **yggdevsec-labs** secure.

## Supported Versions

Security fixes generally target the latest maintained release of each project. Older versions may not receive security updates. If a repository has its own security policy or version-support information, that information takes precedence.

## Reporting a Vulnerability

If you discover a potential security vulnerability in a yggdevsec-labs project:

1. Go to the **affected repository** on GitHub.
2. If available, use **Security → Advisories → Report a vulnerability** to submit a private report.
3. Include the affected repository and version or commit, a description of the issue, reproduction steps, potential impact, and any suggested mitigation.

**Do not disclose vulnerability details in a public issue, discussion, or pull request.**

If private vulnerability reporting is not enabled for the affected repository, please report the vulnerability privately to **dev@yggdevsec.com**.

## Handling Reports

We will review reports and assess their impact. We may request additional information to reproduce and resolve an issue. Where appropriate, we will coordinate disclosure after a fix or mitigation is available.

Please avoid testing that disrupts services, accesses data belonging to others, or causes damage.

## Scope

This policy applies as the default security policy for public repositories owned by **yggdevsec-labs**, unless a repository defines its own `SECURITY.md`.
